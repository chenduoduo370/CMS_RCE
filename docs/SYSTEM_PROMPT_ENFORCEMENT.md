# SYSTEM_PROMPT 强化 - 禁止建议输出

## 问题发现
虽然之前优化了 SYSTEM_PROMPT 要求 AI 简洁输出，但实际测试中 AI 仍然输出了冗长的安全建议。

**原因**：规则措辞不够严格，用了"请"、"不要"等软性表述，AI 理解不够强硬。

## 解决方案

修改 SYSTEM_PROMPT 中"测试完成后的回复规则"，从柔性规则改为强制性规则。

### 优化前（柔性措辞）
```
请按以下格式简洁地总结结果：
1. 简要说明...
2. 列出发现的 CVE...
3. 显示成功率...
4. 仅在用户主动询问"建议"、"怎么修复"等时再提供安全建议
5. 不要主动输出冗长的修复建议...
```

**问题**：
- "请"、"不要"等词汇强度不够
- AI 可能误解为"建议不要输出"而不是"禁止输出"

### 优化后（强制性规则）
```
你的回复必须严格按照以下格式：
1. 简要说明...
2. 列出发现的 CVE...
3. 显示成功率...
4. 仅此而已，不输出任何额外内容

重要：
  - 禁止输出任何修复建议、WAF 规则、升级步骤
  - 禁止输出任何安全加固措施
  - 禁止输出任何培训或教学内容
  - 如果用户需要建议，他们会主动询问
  - 那时才输出相关内容
  - 否则只输出结果摘要（3-4 行）
```

**改进**：
- "必须严格按照" → 强制性
- "禁止输出" 明确列举 → 无歧义
- "仅此而已" → 绝对边界

## 预期效果

### 优化后的输出（现在应该是这样）
```
测试完成，结果汇总如下：

- 目标：192.168.10.111:82 和 192.168.10.111:83
- 成功利用漏洞：
  ✅ CVE-2018-7600（端口 82、83）
  ✅ CVE-2019-6340（端口 83）
- 成功率：2/2 (100%)
```

不会再有：
- ❌ "建议升级 Drupal 核心"
- ❌ WAF 规则配置
- ❌ "临时缓解措施"
- ❌ "纵深防御加固"

## 用户需要建议时

如果用户询问："这些漏洞怎么修复？" 或 "给点安全建议"

**那时 AI 会输出**：
```
根据测试结果，建议以下修复步骤：
1. 升级 Drupal 核心...
2. 临时缓解措施...
...
```

## 技术原理

SYSTEM_PROMPT 中的规则被 LLM（千问）用作行为约束。

- **强制性措辞**（"必须"、"禁止"）被理解为硬性规则
- **柔性措辞**（"请"、"不要"）可能被理解为建议或示例

通过明确的禁止列表和"仅此而已"的边界定义，确保 AI 严格遵循。
